Authentication

Two token types: your Veyra account session (from POST /api/auth/login) manages workspaces and keys; an API key (vyr_live_…) calls the public API. Both travel as Authorization: Bearer .

# 1. Sign in to get a session token (management API)
curl -s -X POST $API/api/auth/login \
  -H 'content-type: application/json' \
  -d '{"email":"you@example.com","password":"•••"}'
# → {"ok":true,"token":"v1.…","user":{…}}

# 2. Create a workspace with that session token
curl -s -X POST $API/api/platform/workspaces \
  -H "authorization: Bearer $TOKEN" -H 'content-type: application/json' \
  -d '{"name":"My Dev Workspace","description":"docs crawler"}'
# → {"ok":true,"workspace":{"id":"…","slug":"my-dev-workspace",…}}

# 3. Create an API key — the secret is returned exactly once
curl -s -X POST $API/api/platform/workspaces/$WS_ID/keys \
  -H "authorization: Bearer $TOKEN" -H 'content-type: application/json' \
  -d '{"name":"Production key"}'
# → {"ok":true,"key":"vyr_live_•••","keyInfo":{"id":"…","last4":"abcd"},…}

# 4. Call the public API with the key
curl -s $API/api/v1/me -H "authorization: Bearer $VYR_KEY"
# → {"ok":true,"workspace":{…},"key":{…},"usage":{"requests":1,…}}

Management endpoints

session token
EndpointDescription
GET /api/platform/overviewAccount snapshot: workspaces, keys, billing, limits, pricing.
GET /api/platform/pricingPublic plan catalogue (owner, developer, early access, team).
POST /api/platform/workspacesCreate a workspace (name, optional description). Errors: WORKSPACE_NAME_INVALID, PLATFORM_PLAN_LIMIT.
PATCH /api/platform/workspaces/:idRename or edit the description.
DELETE /api/platform/workspaces/:idDelete a workspace and orphan its keys.
GET /api/platform/workspaces/:id/keysList active keys (no secrets — hash and last-4 only at rest).
POST /api/platform/workspaces/:id/keysCreate a key; the raw secret is returned once. Errors: BILLING_REQUIRED, PLATFORM_KEY_LIMIT, API_KEY_NAME_INVALID.
PATCH /api/platform/workspaces/:ws/keys/:keyRename a key.
POST /api/platform/workspaces/:ws/keys/:key/rotateRevoke the old secret and mint a new one (shown once).
DELETE /api/platform/workspaces/:ws/keys/:keyRevoke a key immediately.
POST /api/platform/billing/setupSave a billing profile (required before issuing keys on the Developer plan).
POST /api/platform/waitlistJoin the early-access waitlist. Errors: WAITLIST_EMAIL_INVALID, PLATFORM_RATE_LIMITED.

Public API

api key
EndpointDescription
GET /api/v1/meIdentity of the key: workspace, key metadata and usage counters.
GET /api/v1/usageUsage for the key: totals, rolling 24h window and per-hour buckets.
 
# Usage with hourly buckets (requires the key)
curl -s $API/api/v1/usage -H "authorization: Bearer $VYR_KEY"
# → {"ok":true,"keyId":"…","usage":{"requests":12,"last24h":3,…},"byHour":{"2026-11-13T20:00:00Z":2,…}}

# Errors use a consistent envelope: {"error":"…","code":"…"}
# 401 PLATFORM_KEY_REQUIRED / PLATFORM_KEY_INVALID · 429 PLATFORM_RATE_LIMITED

All platform routes are rate limited (120 requests/minute per IP; the waitlist form allows 5 per hour). Key-authenticated calls count towards that key’s usage.
