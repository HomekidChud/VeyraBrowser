Documentation / API v1

Fetch a webpage

Send a public URL to Veyra and get its HTML or JSON back. Use the response in your backend, or show a static preview in your app.

01

Make your first request

Create an API key in the console and set VYR_KEY as a secret environment variable on your server. Then request https://example.com/:

# Set VYR_KEY in your environment before running this.
curl --fail-with-body -sS https://veyraserver-xscy.onrender.com/api/v1/fetch \
  -H "Authorization: Bearer $VYR_KEY" \
  --json '{"url":"https://example.com/","format":"text"}'
// Save as fetch-page.mjs and run with Node.js 20+.
const r = await fetch("https://veyraserver-xscy.onrender.com/api/v1/fetch", {
  method: "POST",
  headers: {
    Authorization: `Bearer ${process.env.VYR_KEY}`,
    "Content-Type": "application/json",
  },
  body: JSON.stringify({ url: "https://example.com/", format: "text" }),
  signal: AbortSignal.timeout(25000),
});
const page = await r.json();
if (!r.ok) throw new Error(page.error);
if (page.status >= 400) throw new Error(`Upstream HTTP ${page.status}`);
if (page.truncated) throw new Error("The page exceeded the response limit");
console.log(page.body);
# python -m pip install requests
import os
import requests

r = requests.post(
    "https://veyraserver-xscy.onrender.com/api/v1/fetch",
    headers={"Authorization": f"Bearer {os.environ['VYR_KEY']}"},
    json={"url": "https://example.com/", "format": "text"},
    timeout=30,
)
r.raise_for_status()
page = r.json()
if page["status"] >= 400:
    raise RuntimeError(f"Upstream HTTP {page['status']}")
if page.get("truncated"):
    raise RuntimeError("The page exceeded the response limit")
print(page["body"])

Check both statuses: the HTTP status describes your call to Veyra; status in the JSON is the response from the website. Use finalUrl to see where redirects ended.

02

Show a preview in your app

Fetch from your backend, sanitize the returned HTML, and serve it on your own preview route. Your browser loads that route in a sandboxed iframe. It never receives your Veyra key.

Runnable Node.js preview
preview.mjs
// npm install express sanitize-html
// Set VYR_KEY, then run: node preview.mjs
import express from "express";
import sanitizeHtml from "sanitize-html";

const app = express();
app.get("/", (_req, res) => {
  res.type("html").send(
    '<iframe src="/preview" sandbox title="Page preview" width="640" height="350"></iframe>'
  );
});
app.get("/preview", async (_req, res) => {
  try {
    const r = await fetch("https://veyraserver-xscy.onrender.com/api/v1/fetch", {
      method: "POST",
      headers: {
        Authorization: `Bearer ${process.env.VYR_KEY}`,
        "Content-Type": "application/json",
      },
      body: JSON.stringify({ url: "https://example.com/", format: "text" }),
      signal: AbortSignal.timeout(25000),
    });
    const page = await r.json();
    if (!r.ok || page.status >= 400 || page.truncated ||
        !/^text\/html\b/i.test(page.contentType || "")) {
      return res.status(502).type("text").send("Preview unavailable");
    }
    const markup = sanitizeHtml(page.body, {
      allowedTags: ["h1", "h2", "h3", "p", "strong", "em", "ul", "ol", "li", "pre", "code"],
      allowedAttributes: {},
    });
    res.set("Content-Security-Policy", "default-src 'none'; sandbox");
    res.type("html").send(`<!doctype html><meta charset="utf-8">${markup}`);
  } catch {
    res.status(502).type("text").send("Preview unavailable");
  }
});
app.listen(3000, "127.0.0.1");

Open http://127.0.0.1:3000/. The sample uses a fixed URL so visitors cannot spend your quota fetching arbitrary pages through your app.

Need the interactive website? Use the publisher’s official embed URL, if available, or open the site in a new tab. The fetch API returns a snapshot, not a browser session: it does not run scripts, load subresources, or provide an iframe URL. Never put a key in an iframe URL or insert a raw response into your app’s DOM.

03

Read the response

body / json
UTF-8 text by default; use "format":"json" for a parsed JSON value.
contentType
Check the returned MIME type before treating a response as HTML.
truncated
If true, the body is incomplete or empty because it exceeded the text limit. Do not render it as a complete page.

API reference

Explore endpoints for fetching pages, searching the index, and monitoring workspace keys.

Status & identity

GET/api/v1/statuspublicAPI liveness, version and rate limits — no key needed

Liveness check for the public API. Returns the server version, uptime and the documented rate limit. The one endpoint that needs no authentication.

curl -s $API/api/v1/status
→ {"ok":true,"api":"veyra","version":"8.21.0","uptimeSeconds":3600,
   "rateLimit":{"max":120,"windowMs":60000},
   "docs":"https://homekidchud.github.io/VeyraBrowser/web/dev/platform/"}
GET/api/v1/verifyapi keyKey check: identity + usage snapshot

Lightweight key validation. Returns the key’s identity, its workspace and current usage counters. Perfect for a “connection test” button in your app.

curl -s $API/api/v1/verify -H "authorization: Bearer $VYR_KEY"
→ {"ok":true,"valid":true,"key":{"id":"key-uuid","name":"Production key","last4":"abcd","createdAt":"2026-11-17T15:00:00.000Z"},
   "workspace":{"id":"workspace-uuid","name":"Demo","slug":"demo"},
   "usage":{"requests":7,"last24h":2}}
GET/api/v1/meapi keyThe key’s full identity and usage counters

Identity of the calling key: workspace, key metadata and usage counters.

curl -s $API/api/v1/me -H "authorization: Bearer $VYR_KEY"
→ {"ok":true,"workspace":{"id":"workspace-uuid","name":"Demo","slug":"demo"},
   "key":{"id":"key-uuid","name":"Production","last4":"abcd","createdAt":"2026-11-17T15:00:00.000Z"},
   "usage":{"requests":1,"last24h":1,"lastUsedAt":"2026-11-17T16:00:00.000Z"}}

Keys

GET/api/v1/keysapi keyList the keys in this key’s workspace

List active keys in the calling key’s workspace. Use the returned IDs to look up a key’s metadata and usage.

curl -s $API/api/v1/keys -H "authorization: Bearer $VYR_KEY"
→ {"ok":true,"workspace":{"id":"workspace-uuid","slug":"demo"},"total":1,
   "keys":[{"id":"key-uuid","name":"Production","last4":"abcd","createdAt":"2026-11-17T15:00:00.000Z",
            "lastUsedAt":"2026-11-17T16:00:00.000Z","revokedAt":null,
            "usage":{"requests":1,"last24h":1,"byHour":{"2026-11-17T16:00:00Z":1}}}]}
GET/api/v1/keys/:idapi keyOne key’s metadata and usage counters
ParamTypeDescription
idpathThe key’s UUID (from GET /api/v1/keys).
curl -s $API/api/v1/keys/$KEY_ID -H "authorization: Bearer $VYR_KEY"
→ {"ok":true,"key":{"id":"key-uuid","name":"Production","last4":"abcd","createdAt":"2026-11-17T15:00:00.000Z",
                   "lastUsedAt":null,"revokedAt":null,"usage":{"requests":0,"last24h":0,"byHour":{}}},
   "usage":{"requests":0,"last24h":0,"window":[]}}

An ID not found in the workspace returns 404 API_KEY_NOT_FOUND.

Usage

GET/api/v1/usageapi keyUsage totals, rolling 24h window and per-hour buckets

Usage for the calling key: totals, the rolling 24h window and per-hour buckets.

curl -s $API/api/v1/usage -H "authorization: Bearer $VYR_KEY"
→ {"ok":true,"keyId":"key-uuid",
   "usage":{"requests":12,"last24h":3,"lastUsedAt":"2026-11-17T16:00:00.000Z"},
   "byHour":{"2026-11-17T15:00:00Z":2,"2026-11-17T16:00:00Z":1}}
GET/api/v1/usage/hoursapi keyExactly 24 hourly buckets, zero-filled

The last 24 hours of requests for the calling key as hourly buckets — every hour present, zero-filled, ready to chart.

curl -s $API/api/v1/usage/hours -H "authorization: Bearer $VYR_KEY"
→ {"ok":true,"keyId":"key-uuid","windowHours":24,
   "hours":{"2026-11-17T15:00:00Z":0,"2026-11-17T16:00:00Z":4}}

The sample shows two buckets for brevity. The API returns all 24.

Search

GET/api/v1/searchapi keySearch the Veyra index
ParamTypeDescription
qqueryRequired. The search term.
limitqueryMax results (default 10, capped by the server).
offsetqueryResult offset for paging.
curl -s "$API/api/v1/search?q=veyra&limit=5" -H "authorization: Bearer $VYR_KEY"
→ {"ok":true,"total":0,"results":[],"indexSize":42,"terms":["veyra"],
   "filters":{},"provider":"veyra-index","responseTimeMs":3}

A blank query returns 400 SEARCH_QUERY_REQUIRED. A query with no matches returns an empty results array.

GET/api/v1/suggestapi keySearch suggestions
ParamTypeDescription
qqueryThe partial term to complete.
curl -s "$API/api/v1/suggest?q=vey" -H "authorization: Bearer $VYR_KEY"
→ {"ok":true,"suggestions":["veyra"]}

Fetch

POST/api/v1/fetchapi keyRetrieve HTML, text or JSON from a public URL

Fetch a public HTTP(S) URL without running page scripts. Text responses are capped at 256 KiB; JSON responses have a separate server-side limit. The result is data, not an iframe URL. See the static preview guide.

ParamTypeDescription
urlbodyRequired. A public http(s) URL. Private addresses are blocked.
formatbody"text" (default) or "json" — parse the body as JSON and return it inline.
curl -s -X POST $API/api/v1/fetch -H "authorization: Bearer $VYR_KEY" \
  -H 'content-type: application/json' -d '{"url":"https://example.com/"}'
→ {"ok":true,"status":200,"url":"https://example.com/","finalUrl":"https://example.com/",
   "contentType":"text/html","truncated":false,"body":"<!doctype html><h1>Example Domain</h1>"}

Invalid URL: 400 FETCH_URL_INVALID. Invalid or oversized JSON: 422 FETCH_NOT_JSON. Blocked or unreachable destination: 502 FETCH_FAILED.

Authentication and errors

Send Authorization: Bearer $VYR_KEY on protected /api/v1 requests. Status is public. Authenticated calls count toward key usage; the v1 limit is 120 requests per minute per IP.

401
PLATFORM_KEY_REQUIRED or PLATFORM_KEY_INVALID: add a valid, active API key.
429
PLATFORM_RATE_LIMITED: pause before retrying; use backoff for repeated calls.
502
FETCH_FAILED: the target was unavailable or could not be fetched. Check the URL and returned error message.
Management API: workspaces, keys and billing

Use a Veyra account session token for management, not a workspace key. Pricing and waitlist submission are public.

EndpointDescription
GET /api/platform/overviewAccount snapshot: workspaces, keys, billing, limits, pricing.
GET /api/platform/pricingPublic plan catalogue (owner, developer, early access, team).
POST /api/platform/workspacesCreate a workspace (name, optional description). Errors: WORKSPACE_NAME_INVALID, PLATFORM_PLAN_LIMIT.
PATCH /api/platform/workspaces/:idRename or edit the description.
DELETE /api/platform/workspaces/:idDelete a workspace and orphan its keys.
GET /api/platform/workspaces/:id/keysList active key names, IDs, last four characters and usage.
POST /api/platform/workspaces/:id/keysCreate a key; the raw secret is returned once. Errors: BILLING_REQUIRED, PLATFORM_KEY_LIMIT, API_KEY_NAME_INVALID.
PATCH /api/platform/workspaces/:ws/keys/:keyRename a key.
POST /api/platform/workspaces/:ws/keys/:key/rotateRevoke the old secret and mint a new one (shown once).
DELETE /api/platform/workspaces/:ws/keys/:keyRevoke a key immediately.
POST /api/platform/billing/setupSave a billing profile (required before issuing keys on the Developer plan).
POST /api/platform/waitlistJoin the early-access waitlist. Errors: WAITLIST_EMAIL_INVALID, PLATFORM_RATE_LIMITED.
