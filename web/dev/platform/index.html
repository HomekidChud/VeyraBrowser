Quickstart

From zero to your first API call in three steps. Create a workspace and key in the tabs above, then use the key from your own code.

  1. Create a workspace and an API key. The secret (vyr_live_…) is revealed once — the eye toggle in the modal keeps it hidden until you click it, and Veyra stores only a hash.
  2. Send it as a Bearer token. Every /api/v1 call carries Authorization: Bearer $VYR_KEY.
  3. Watch usage climb. Every authenticated call is counted per key on the Usage tab and via GET /api/v1/usage.
# Sign in for a session token, create a workspace, mint a key
curl -s -X POST $API/api/auth/login -H 'content-type: application/json' \
  -d '{"email":"you@example.com","password":"•••"}'

curl -s -X POST $API/api/platform/workspaces \
  -H "authorization: Bearer $TOKEN" -H 'content-type: application/json' \
  -d '{"name":"My Dev Workspace","description":"docs crawler"}'

curl -s -X POST $API/api/platform/workspaces/$WS_ID/keys \
  -H "authorization: Bearer $TOKEN" -H 'content-type: application/json' \
  -d '{"name":"Production key"}'

# Then call the public API with the key
curl -s $API/api/v1/me -H "authorization: Bearer $VYR_KEY"
// Browser or Deno — same shape everywhere.
const API = "https://veyraserver-xscy.onrender.com";
const key = "vyr_live_…"; // created in the API keys tab — shown once

const r = await fetch(`${API}/api/v1/me`, {
  headers: { authorization: `Bearer ${key}` }
});
console.log(await r.json());
# pip install requests
import requests

API = "https://veyraserver-xscy.onrender.com"
key = "vyr_live_…"  # created in the API keys tab — shown once

r = requests.get(f"{API}/api/v1/me", headers={"authorization": f"Bearer {key}"})
print(r.json())
// Node 18+ has global fetch.
const API = "https://veyraserver-xscy.onrender.com";
const key = "vyr_live_…";

const r = await fetch(`${API}/api/v1/search?q=veyra`, {
  headers: { authorization: `Bearer ${key}` }
});
console.log(await r.json());

Authentication

Two token types: your Veyra account session (from POST /api/auth/login) manages workspaces and keys; an API key (vyr_live_…) calls the public API. Both travel as Authorization: Bearer . All platform routes are rate limited (120 requests/minute per IP; the waitlist form allows 5 per hour). Key-authenticated calls count towards that key’s usage.

401 PLATFORM_KEY_REQUIRED — no Bearer key on a protected route
401 PLATFORM_KEY_INVALID — revoked or unknown key
429 PLATFORM_RATE_LIMITED — too many requests this minute
402 BILLING_REQUIRED — set up billing before issuing keys

Public API reference

Every /api/v1 endpoint, what it takes, what it returns. Click an endpoint to expand its parameters and examples.

Status & identity

GET/api/v1/statuspublicAPI liveness, version and rate limits — no key needed

Liveness check for the public API. Returns the server version, uptime and the documented rate limit. The one endpoint that needs no authentication.

curl -s $API/api/v1/status
→ {"ok":true,"api":"veyra","version":"8.21.0","uptimeSeconds":3600,
   "rateLimit":{"max":120,"windowMs":60000},"docs":"…"}
GET/api/v1/verifyapi keyKey check: identity + usage snapshot

Lightweight key validation. Returns the key’s identity, its workspace and current usage counters. Perfect for a “connection test” button in your app.

curl -s $API/api/v1/verify -H "authorization: Bearer $VYR_KEY"
→ {"ok":true,"valid":true,"key":{"id":"…","name":"Production key","last4":"abcd",…},
   "workspace":{"id":"…","name":"My Dev Workspace","slug":"my-dev-workspace"},
   "usage":{"requests":7,"last24h":2}}
GET/api/v1/meapi keyThe key’s full identity and usage counters

Identity of the calling key: workspace, key metadata and usage counters.

curl -s $API/api/v1/me -H "authorization: Bearer $VYR_KEY"
→ {"ok":true,"workspace":{…},"key":{…},"usage":{"requests":1,"last24h":1,"lastUsedAt":"…"}}

Keys

GET/api/v1/keysapi keyList the keys in this key’s workspace

The active keys in the workspace the calling key belongs to. Only public metadata — hashed secrets never leave the server.

curl -s $API/api/v1/keys -H "authorization: Bearer $VYR_KEY"
→ {"ok":true,"workspace":{"id":"…","slug":"my-dev-workspace"},"total":2,
   "keys":[{"id":"…","name":"Production key","last4":"abcd","usage":{…}},…]}
GET/api/v1/keys/:idapi keyOne key’s metadata and usage counters
ParamTypeDescription
idpathThe key’s UUID (from GET /api/v1/keys).
curl -s $API/api/v1/keys/$KEY_ID -H "authorization: Bearer $VYR_KEY"
→ {"ok":true,"key":{"id":"…","name":"Production key","last4":"abcd",…},"usage":{…}}
# 404 {"error":"API key not found.","code":"API_KEY_NOT_FOUND"}

Usage

GET/api/v1/usageapi keyUsage totals, rolling 24h window and per-hour buckets

Usage for the calling key: totals, the rolling 24h window and per-hour buckets.

curl -s $API/api/v1/usage -H "authorization: Bearer $VYR_KEY"
→ {"ok":true,"keyId":"…","usage":{"requests":12,"last24h":3,…},
   "byHour":{"2026-11-13T20:00:00Z":2,…}}
GET/api/v1/usage/hoursapi keyExactly 24 hourly buckets, zero-filled

The last 24 hours of requests for the calling key as hourly buckets — every hour present, zero-filled, ready to chart.

curl -s $API/api/v1/usage/hours -H "authorization: Bearer $VYR_KEY"
→ {"ok":true,"keyId":"…","windowHours":24,
   "hours":{"2026-11-16T17:00:00Z":0,…,"2026-11-17T16:00:00Z":4}}

Search

GET/api/v1/searchapi keySearch the Veyra index
ParamTypeDescription
qqueryRequired. The search term.
limitqueryMax results (1–20, default 10).
offsetqueryResult offset for paging.
curl -s "$API/api/v1/search?q=veyra&limit=5" -H "authorization: Bearer $VYR_KEY"
→ {"ok":true,"results":[…],"provider":"veyra-index","responseTimeMs":3}
# 400 {"error":"Provide a search term: ?q=…","code":"SEARCH_QUERY_REQUIRED"}
GET/api/v1/suggestapi keySearch suggestions
ParamTypeDescription
qqueryThe partial term to complete.
curl -s "$API/api/v1/suggest?q=vey" -H "authorization: Bearer $VYR_KEY"
→ {"ok":true,"suggestions":["veyra browser","veyra api",…]}

Fetch

POST/api/v1/fetchapi keyFetch any public URL through Veyra’s proxy infrastructure

Fetches a public URL server-side through the same infrastructure as the fast proxy (SSRF guards, DNS checks, caching) and returns the body as text or parsed JSON. The body is capped at 256KB.

ParamTypeDescription
urlbodyRequired. A public http(s) URL. Private addresses are blocked.
formatbody"text" (default) or "json" — parse the body as JSON and return it inline.
curl -s -X POST $API/api/v1/fetch -H "authorization: Bearer $VYR_KEY" \
  -H 'content-type: application/json' -d '{"url":"https://example.com/"}'
→ {"ok":true,"status":200,"finalUrl":"https://example.com/",
   "contentType":"text/html; charset=UTF-8","body":"…"}
# 400 {"code":"FETCH_URL_INVALID"} · 422 {"code":"FETCH_NOT_JSON"}
# 502 {"code":"FETCH_FAILED"} — includes Veyra’s SSRF guard message
